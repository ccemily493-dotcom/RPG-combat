# Universal RPG Engine v0.3.1 + v0.4 — Completion Report

## v0.3.1

### 1–7. Scheduler, execution classes, zero time, economy, partials, and goals

v0.3.1 replaces the provisional dependency-layer cadence with iterative deterministic scheduling. `ZERO_TIME`, `ACTION`, `REACTION`, `MOVEMENT`, and `PASSIVE` are explicit. Zero-time nodes chain within a step; a configured limit of 64 raises a structured error before caller state can change. Economy nodes reserve and consume only their declared capacity, with movement-to-action fallback retained for old character snapshots.

The scheduler may run action → zero-time condition/branch → action in one turn when capacity exists. With insufficient capacity the second action stays pending until recovery on a later turn. `SUCCESS`, `PARTIAL`, and `FAILURE` are retained; `ON_SUCCESS` rejects partial while `ON_PARTIAL` and `ON_PARTIAL_OR_BETTER` are available. Structural `COMPLETED` state is separate from required/optional goal outcomes. `ALL_TERMINAL` is the default; `REQUIRED_GOALS`, `ANY_GOAL`, and `EXPLICIT_PREDICATE` are supported without a plan score.

### 8–12. Scenarios, invariants, replays, performance, ambiguities

All requested v0.3.1 behaviors are covered in `test/v031.test.js` plus session/invariant tests: zero-time branching, two same-turn actions, insufficient economy, strict partial dependencies, failed required goals, fallback paths, safety-limit rollback, direct/strategy equivalence, and high/low-economy execution of one DAG.

The v0.3.1 checkpoint passed 157/157 tests and INV-001–INV-070 before v0.4 began. Final v0.4 metadata hashes supersede the checkpoint turn/session hashes. Current session performance is reported in `reports/session-performance-v0.3.md`; the five-turn linear DAG median is 3.812 ms/turn and the 20-turn session median is 3.093 ms/turn.

Conservative rules added to configuration/documentation: dependency is not time, movement economy fallback is explicit, new effects are stamped at the resulting turn, and multi-wave combat commits time once.

## v0.4

### 13–17. Architecture, schemas, compilation, instantiation, expressions

The Ability Parser lives under `src/ability-parser/` and depends downward on shared engine contracts/utilities. No core engine module imports it. Three formal schemas define ability definitions, compiled artifacts, and runtime uses. Compilation validates namespaces, versions, components, references, parameters, variants, requirements, costs, statuses, defenses, expressions, and provenance; runtime instantiation binds actors/targets/parameters and validates final normalized actions/reactions/Strategy DAGs.

The safe AST implements only `ADD`, `SUBTRACT`, `MULTIPLY`, `DIVIDE`, `MIN`, `MAX`, `CLAMP`, and `ABS`. It rejects forbidden references/operations, non-finite values and division by zero, with limits of 16 levels and 128 nodes. No `eval`, `Function`, arbitrary JavaScript, network call, API key, LLM, or natural-language interpretation exists.

### 18–24. Parameters, contracts, integration, registry, and caching

Parameters support number/integer/boolean/string/enum types, defaults, bounds, and explicit variants. Costs compile directly to existing `PER_ACTION`, `PER_HIT`, `SHARED_POOL`, or `UPFRONT_PLUS_PER_HIT` action contracts. Statuses remain attempts. Defense sources/reactions, movement, multi-target areas, multi-hit quantities, temporal effects, relations/opportunities, resource interactions, and v0.3.1 Strategy DAG fragments reuse existing normalized contracts.

The immutable registry rejects duplicates/incompatible rulesets and exposes namespaced lookup, snapshots, and a canonical hash. Optional compilation caching keys definition, parser/ruleset versions, and registry hashes. Cache hits and uncached compilation are byte-equivalent. Full definition hashes retain provenance while mechanical hashes ignore presentation-only fields.

### 25–29. Provenance, fixtures, equivalence, tests, diagnostics

Every generated action carries `ability_id`, ability version, compiled mechanical hash, parser version, parameter bindings, and variant provenance in an extension payload. Combat resolution depends on the normalized action, not an ability-specific combat path.

The 12 generic fixtures are Heavy Strike, Rapid Barrage, Guard Field, Dash Strike, Disrupting Shot, Delayed Burst, Prepared Counter, Area Pulse, Resource Suppression, Tactical Opening, Parameterized Blast, and Conditional Follow-up. Scenarios cover compile/use/combat, five-hit cost conservation, defense/reaction filtering, movement economy, status resistance, delayed activation, opportunity creation, multi-target allocation, resource denial, Strategy DAG execution, parameters/variants/branches, invalid references/expressions, and cache equivalence.

Manual and parser-generated byte-identical normalized actions produce identical `resolveTurn` hashes. Diagnostics report 12 abilities, 15 components, 67 expression nodes, one Strategy fragment, zero invalid references, and zero suspicious-value warnings. They are non-blocking and define no balance score.

### 33–36. Ambiguities, provisional defaults, limitations, next milestone

Provisional values are the 16/128 expression limits, suspicious diagnostic thresholds (power 300, range 1,000, quantity 500), caller-owned unbounded cache, explicit target/action binding tokens, and dynamic defense-source lifetime delegated to temporal/session state. They are documented in `open-decisions.md`.

Remaining limitations: definitions remain intentionally verbose; compiled requirement satisfaction needs a dedicated pre-declaration adapter; no persistent cache/database exists; geometry/pathfinding/physics remain minimal; the semantic-provider interface has no implementation; there is no natural-language parser, universe extension, optimizer, AI, narration, networking, or automatic balancing.

Recommended next milestone: v0.4.1 authoring hardening and randomized compiler/property fuzzing, with stable schema URIs and an explicit requirement-evaluation adapter. Do not begin semantic/LLM or universe work without a separate authorization.
