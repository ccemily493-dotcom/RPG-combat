# Universal RPG Engine v0.5 — Completion Report

Generated 2026-09-05. Milestone status: **complete**.

Added `semantic.yaml`, three Semantic Input JSON Schemas, six semantic CLI/support tools, twenty deterministic scenario fixtures, five goldens, two test files, two diagnostics reports, two performance reports, and this completion report.

Updated Ability Definition/Compiled Ability schemas and fixtures to expose locale aliases while excluding them from mechanical hashes. Updated validation, package scripts/version, invariants, tests, README, open decisions, affected replay metadata, and regenerated performance/diagnostic reports.

## 2. Semantic Input architecture

The new layer is architecturally separate. Its pipeline is:

`text → normalization/token spans → dictionary/rules → entity binding → confidence → validated SemanticIntent → explicit binder → existing Ability Parser/engine contracts`.

It does not call an RPG outcome resolver and cannot mutate canonical state.

## 3. Schemas created

- `semantic-dictionary-entry.schema.json`
- `semantic-intent.schema.json`
- `semantic-parse-result.schema.json`

All three compile under Draft 2020-12. Fallback candidates validate against the same intent schema before any binder can see them.

## 4. Normalization/tokenization

Unicode NFKC, quote normalization, locale-aware lowercase conversion, diacritic-folded matching, punctuation removal, and token offsets are deterministic. Original text and source spans remain available for errors/UI highlighting. Input length and sequence length are configured and bounded.

## 5. Spanish and English rule layer

Spanish and English are data packages, not core branches. The baseline covers attacks/delivery modes, defense/reactions, movement, object interaction, ability invocation, wait/observe, target/aim concepts, and all v0.3 strategic primitives. Locale detection and conservative morphology hooks are exposed without adding semantic guessing.

## 6. Dictionary/registry system

Compiled immutable dictionaries support namespaces, locale/version/source metadata, surface forms, priority, constraints, collision diagnostics, deterministic hashes, and compilation caching. Precedence is explicitly `SESSION → EXTENSION → CHARACTER → ABILITY → LOCALE → UNIVERSAL`; file and synonym order do not alter canonical candidates.

Validated fixture sizes: Spanish 50 entries/94 surfaces; English 57 entries including registered ability aliases. Spanish fixture collisions: zero.

## 7. Entity resolution

Stable entity IDs are resolved from explicit names, aliases, declared focus/default targets, supplied distances, and supplied spatial labels. Unique “closest” resolution is allowed. Ambiguities return candidate IDs for clarification. “Best target” is never chosen because that would be tactical authority.

## 8. Intent detection/decomposition

The layer distinguishes action, ability use, sequence, strategy, wait/observe, ambiguity, and unresolved input. It extracts actor/targets, delivery subtype, body zone, direction, numeric distance, intensity, quantity, object reference, execution class, and strategic primitive. Multi-clause order and explicit dependencies are preserved; self-correction uses the final explicit entity reference.

## 9. Confidence policy

Confidence is recorded per field plus an overall diagnostic value. Provisional configured thresholds are direct accept 0.90, optional-field accept 0.80, and fallback boundary 0.65. Confidence never modifies RPG calculations.

## 10. Semantic fallback boundary

`SemanticFallbackProvider` is an interface only. A deterministic mock exists for tests and benchmarks. No live implementation, network call, API key, prompt, vendor SDK, or LLM dependency exists. Invalid schemas, entities, abilities, action types, or outcome-authority fields are rejected before compilation.

## 11. Cache

Phrase and context caches are optional and non-mechanical. Keys include normalized phrase, locale, parser version, dictionary hash, ability-registry hash, and normalized entity/context signature. Cache/no-cache paths compile to identical mechanics; stale hashes partition entries deterministically.

## 12. Candidate learning

Unknown phrases may be retained with occurrence counts, confidence observations, fallback sources, and bounded context signatures. Automatic promotion is forbidden and throws if requested. Canonical vocabulary changes require an external explicit review workflow.

## 13. Ability Parser integration

Registered ability aliases compile from presentation-only definition data. A semantic ability use delegates to the public v0.4 instantiator, producing the existing action/reaction/temporal/strategy payloads. Alias changes alter full-definition provenance but not an ability's mechanical hash.

## 14. Strategy DAG integration

Semantic sequences/strategies compile to existing v0.3.1 execution classes and dependencies. Action-backed nodes require explicit normalized action templates; primitives retain ordinary scheduler/economy semantics. Semantic orchestration adds no score, free economy, success, or payoff.

## 15. Explicit action-template binding

Direct verbs identify an attempted action class only. The binder requires a caller-supplied normalized action template, then binds IDs, actor, targets, quantity, zone, movement distance, and execution class. It never invents power, speed, accuracy, penetration, damage, costs, defense, or status success.

## 16. Mechanical equivalence

Tests prove identical normalized actions resolve identically whether manually authored or produced by Semantic Input. Rule-generated and mock-fallback-generated identical `SemanticIntent` objects also compile identically. Trace/diagnostic switches do not change intent or mechanics.

## 17. Security/authority validation

Semantic objects recursively reject final damage, hit, critical, defense outcome, status application, resource outcome, incapacitation, strategy success, final state, and state-delta fields. The package contains no `eval`, `new Function`, process execution, arbitrary JavaScript predicates, or engine resolver calls.

## 18. Architecture boundaries

- Core → Semantic Input dependency violations: **0**
- Ability Parser → Semantic Input dependency violations: **0**
- Semantic Input → engine outcome-resolver violations: **0**
- Semantic Input outcome-authority violations: **0**

The only downward semantic dependency is the final binder's use of public Ability Parser/schema APIs.

## 29. No-franchise/no-vendor audit

The universal semantic package contains no franchise resource model, named fictional ability logic, universe extension, LLM SDK, provider client, networking code, or API-key path. Extension vocabulary remains supplied as ordinary namespaced dictionary data.

## 30. Specification ambiguities resolved conservatively

Minor choices were placed in `semantic.yaml` or schemas: supported initial locales, confidence thresholds, namespace precedence, input/sequence/candidate limits, cache behavior, and disabled automatic promotion. Tactical-best selection remains unresolved by design. Direct action mechanics require explicit templates instead of guessed coefficients.

## 31. Suspicious provisional values

The confidence thresholds lack real player-corpus calibration. Locale morphology is intentionally narrow. A 50,000-entry compiled dictionary's coarse memory cost suggests future tooling should persist or bound compiled artifacts. None of these findings authorize semantic guessing, live fallback, or balance retuning.

## 32. Remaining limitations

No live fallback provider, long-form discourse model, persisted editorial database, automatic vocabulary promotion, broad multilingual coverage, semantic strategy optimizer, AI target selector, or narrative interpretation exists. Direct semantic commands depend on explicit action-template catalogs; semantic parsing does not make definitions mechanically complete.

## 33. Recommended next milestone

A bounded v0.5.1 hardening milestone could add representative corpora, randomized schema/authority fuzzing, locale-package authoring tools, collision review tooling, and persisted compiled-dictionary artifacts. It should not add a live LLM or universe extension without a separate explicit authorization and policy decision.

No later milestone was started.
